# 公共下载与代理

网络设置分为“下载与插件市场”和“模型 API”，共用代理地址、各自选择连接方式。插件市场默认跟随公共下载，也可显式展开独立设置；已有不同设置会保留并展开。模型 API 是另一个独立用途：启用模型 API 代理不会自动开启下载代理，关闭模型 API 代理也不会关闭已经启用的下载代理。

## 来源顺序

- 镜像优先：先尝试镜像，失败后尝试官方源。
- 官方优先：先尝试官方源，失败后尝试镜像。
- 镜像始终直接连接，不使用系统代理、环境变量代理或模型 API 代理。
- 单次模型下载页面明确选择来源时，以该次选择为准：选择官方只使用官方源；选择镜像时允许失败后尝试官方源。其官方连接方式仍遵守这里的设置。

## 官方连接方式

| 选择 | 官方请求行为 |
| --- | --- |
| 直接连接 | 不使用代理 |
| 代理优先，失败后直连 | 先访问填写的代理；失败后直接连接同一个官方源 |
| 仅使用代理 | 代理不可用就返回错误，不自动改成官方直连 |

例如，镜像优先加允许代理回退的完整顺序是：镜像直连 → 官方代理 → 官方直连。官方优先时是：官方代理 → 官方直连 → 镜像直连。某个来源不适用时跳过，不用不可信的来源替代核验。

Core 更新摘要与镜像插件的文件清单必须向官方核验。该请求遵守官方连接方式，但不会为了更新成功而信任镜像提供的摘要。摘要核验完成后，更新包正文仍按来源顺序下载，并核对 SHA-256。

## 模型 API

模型 API 提供相同的三个连接选项，独立于公共下载。只有用户显式选择“代理优先，失败后直连”时才允许回退。官方供应商范围仍可分别选择；自定义、局域网和本机 API 地址保持直连。

回退限于 ConnectError、ConnectTimeout、ProxyError 且模型请求头尚未开始发送。HTTPS 代理的 CONNECT 建连不算发送模型请求。发送请求头后，即使异常类型看似连接失败也不回退；HTTP 401/403/429/5xx、读写超时、响应中断、取消都不会在此路由层重发。直连最多尝试一次，失败后正常报错。现有宿主发送许可在回退前再次核对。

该策略覆盖普通模型请求、后台模型请求、官方 ChatGPT 登录与令牌刷新、模型目录及连接探测。保留凭据、请求内容与目标，不切换供应商或 API 地址。任一用途的设置损坏会报错，不静默改走其他路径。

## 配置兼容

仍使用 `model-proxy.json` 与原有 revision 并发保存检查。新增 `downloads_source` / `market_source`（mirror 或 official）、`downloads_fallback` / `market_fallback`（布尔值）。原有 `downloads_enabled` / `market_enabled` 决定该用途是否使用代理。

旧配置缺少新字段时采用镜像优先、不允许代理回退，以保留原先的网络选择。用户可以在界面显式选择允许回退。旧版配置页保存时保留已经设置的来源顺序与回退选项；关闭对应用途的代理时同时关闭其代理回退。保存成功后，新发起的网络请求使用新设置，正在执行的请求保留本次读取的设置。

模型回退使用 `model_fallback`（布尔值），缺省 false；旧客户端保存保留已有值，关闭模型代理时清除。
