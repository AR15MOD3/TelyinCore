## 统一链路

* 只有正式 Console 注册的 memory.profile_add 处理器参与；可信直接库 API 保持兼容，不是任意插件/进程的 OS 沙箱。
* 工具提出画像写入时，固定当前 Bot 内存根、可信当前 batch、scope、来源作者、目标画像与 provider。最多两条源、最多两次 profile 调用，超界拒绝，不截断或跨轮补源。
* 冻结 V3 协议加当前准入口径的 selector → 原生候选 proposal → 作者候选覆盖检查 → 对实际拟写内容单独做无工具的九维全源复核。复核不看 selector 的决定或推理，不复用主轮历史；默认沿用当前所选模型/提供方，不切换用户 DeepSeek 档案。这是独立请求/上下文，不冒称另一个模型或另一组织的独立评审。
* 任一 fail/unknown、字段/nonce/来源/汇总不一致、取消、超时、漂移都不给写许可。不从普通文字补造调用，不强制把 unknown 变 pass，不通过文字相同免除稳定性审核。
* 宿主在全部 profile 候选审查通过后，才创建绑定处理器/内存根/目标/原参数的 task-local 一次性能力，五秒内且上下文未变才可消费。候选对象与 shadow advisory 本身始终无写入能力。
* 交回原 Dispatcher 和原回执账，不替换模型参数；多个 profile 候选有一项失败时本批全部不给许可。底层多文件 IO 仍不是全局事务：实际写入/回执 IO 中途失败必须如实算部分/未确认，不能自动重试。
* ToolWork.with_inner_guard 将整段审查与派发放进原受管子任务；不把跨任务继承当可写许可，不绕开取消和排空责任。

## 有界成本和状态

仅 profile_add 写前触发附加请求，不每条聊天都调用模型。每个写调用最多 selector/proposal/review 三次（传输额外设四次硬上限），每次 2048 输出上限、20 秒；本批最多两项，90 秒总准备上限。零内部重试。
每个 Bot 的 memory 根独立哈希 claim 账，最多 8 个新调用/UTC 日、4096 总记录；满额或损坏/锁竞争拒绝，不自动清空或删除旧账。仅存 hash/日期，不保存原话、账号或密钥。
附加调用可能产生额外延迟和上游费用；失败不会自动换模型。Chat/Responses 编码走当前提供方，Strata 使用已验证的原生强制 Chat 提案路径；其他协议当前明确拒绝，不能悄悄降级到不经门禁写入。
