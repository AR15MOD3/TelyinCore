# memory · 持久资料

> 这里保存这个 Bot 的知识、经历与对人的认识。README 只解释目录，不是一条记忆。

## 目录怎么分

| 目录或文件 | 用途 |
|---|---|
| 知识/ | 已确定的知识、世界资料与参考文档，按现有知识工具查阅 |
| 经历/ | 对话、笔记与整理等经历投影；不是所有运行日志的统一存放处 |
| 画像/ | 对人的事实、关系与现有画像记录 |
| 做法/ | 已有技能与做法的学习、版本或治理资料；是否存在取决于当前功能 |
| 悬着的事/ | 待处理事项与提议；是否存在取决于当前功能 |
| 身份绑定.json | 可选的账号绑定资料；由实际认证与管理流程维护 |

没有某个可选目录，不表示档案损坏。目录说明也不是要求把所有目录立即创建出来。

## 与人格、会话的区别

长期稳定的角色核心在同级 persona/。具体世界资料可以在知识库补充，不应把整个知识库复制到常驻人格里。
会话主记录、事件、模型协议侧上下文与缓存账本还可能位于启动时选定的运行数据根目录。
因此，“清空 memory/”既不等于安全地清空会话，也不等于只删临时缓存。

## README 放在哪里

本说明只放在 memory/ 根层。当前知识与记忆读取器会递归读取知识、经历等指定子树中的 Markdown；
把 README 随意放进这些子树，可能把维护说明当成可检索资料。
不要为了每层目录看起来一致，就递归向知识/、经历/、画像/ 或做法/ 填入说明文件。

## 知识与向量落盘备忘

新建 Bot、批量导入知识，或新增、改名、移除知识与做法时，把索引同步和检索验证算进同一次操作。

1. 确认操作的是当前 Bot 的档案目录与运行数据目录。准备好 `memory/知识/` 和 `memory/做法/`，即使暂时没有内容也要创建这两个目录。
2. 保存原文后，先用项目现有的索引同步流程建立或更新该 Bot 的文本索引 `search/search.sqlite3`。用标题和正文关键词确认新条目搜得到，改名或移除的旧路径已从结果里消失。空库应能正常返回空结果。
3. 若该 Bot 已配置嵌入模型并启用语义检索，再按当前模型构建或补齐向量缓存，并用语义查询验证命中。首次构建依赖已生成的文本索引。已有缓存走正常的增量流程，首次构建工具仅用于创建缺失的缓存。
4. 如果原文已保存但索引同步失败，保留原文，检查运行数据目录下的 `search/.needs-sync` 和同步日志。修复后重试，验证通过再记录完成。

## 维护约定

- 新 Bot 不复制其他 Bot 的真实知识、经历、画像或身份绑定。
- 修改与清理前先备份，按工具规定的格式处理，不手工改写 JSONL 的旧记录。
- 不把失败测试、临时调试输出或性能统计写成角色经历。
- 文件已保存，不代表每轮都会加载；可见范围与检索能力仍由现有代码及权限决定。

## 写入职责

- 人物记录（profile_add）：当前作者有依据的长期信息、近期情况与计划，审核分类后保存。保留“最近”“尚未完成”等限定；记录日期不等于事件发生日期，不自动设置提醒。
- 自述（self_account_add/set）：Bot 自身身份、自我理解，不用来代存他人的事实或绕过画像审核。
- 自我观察（self_observe_add）：暂存待思考的自我观察到悬着的事；并不直接编辑观察与更正。
- 观察与更正：后台整理自身认识如何被证据纠正，可引用来源，不复制人物档案、知识全文或技能手册。
- 作息与习惯：Bot 自己的行为倾向；对方的时间安排和一次反馈不能自动成为 Bot 的习惯。
- 交流偏好（communication_preference）：对方明确提出的交流方式与适用情境；不改 Bot 性格。
- 做法与技能（skill_note）：有适用条件的可复用方法与操作步骤；知识细节留知识库并引用。
- self_note：短期交接便条；不替代人物档案、原始记录或长期知识保存。

工具未成功不等于已有记录，也不会自动排队补写。审核协议异常、短时限流和内容证据不足是不同情况，不要换工具存到自我文档绕过。旧资料迁移前须核对来源、范围并确认目标写入成功，保留原文历史。
